# تحقّق محليّ — زيادة الواجهة ٢: المسودّة المحليّة + استعادة الجلسة + معالجة 419

> **الحالة:** **لم يُدمج** — GitHub Actions متوقّف (فوترة). الدمج ينتظر اخضرار CI على آخر Commit.

## سلسلة الاعتماد

```
main → #60 → #61 → #62 → #65 (واجهة ١: الحفظ التلقائي) → #66 (هذه: المسودّة + 419)
```

## ما لم يُمسّ

لا تغيير في أي عقد خلفي. أُضيفت للصفحة فقط: `sessionExpired`, `draftScope`, `applyDraft()`, `draftDiscarded()`, `markSessionExpired()`، وحدث `builder-node-saved`. `BuilderActionService` و`BuilderActionResponse` و`BuilderErrorCode` كما هي.

## المسودّة المحليّة — القواعد المطبَّقة

- **المفتاح:** `wmt.builder.draft.{tenant_id}.{user_id}.{program_id}.lesson.{lesson_id}` — مستأجر + مستخدم + كورس + نوع المورد + معرّفه. (وللعنصر غير المنشأ بعد: `.new.{clientId}` — الصيغة جاهزة.)
- **يُخزَّن مع المسودّة:** `updatedAt` (وقت آخر تعديل محليّ) و`baseVersion` (نسخة الخادم التي بُنيت عليها).
- **تُكتب المسودّة عند كل ضغطة مفتاح وقبل أي طلب** — لذلك لا يضيع شيء عند 419 أو انقطاع شبكة أو إعادة تحميل.
- **لا استعادة صامتة:** عند فتح الصفحة تُعرض مقارنة صريحة (نسختك المحليّة مقابل نسخة الخادم، مع النسختين الرقميّتين ووقت التعديل) وأمامك «استعادة» أو «تجاهل».
- **الحذف بعد الحفظ المؤكَّد فقط:** الخادم يُطلق `builder-node-saved` عند نجاح مؤكَّد، وعندها فقط يمسح العميل المسودّة. الحفظ المرفوض/المتعارض **لا** يمسحها.
- المسودّة المطابقة لنسخة الخادم تُعتبر ضجيجًا قديمًا وتُنظَّف تلقائيًّا.

## معالجة 419 — التسلسل المطبَّق

1. المسودّة محفوظة محليًّا **أصلًا** (تُكتب مع كل ضغطة).
2. اعتراض استجابة 419 من Livewire ومنع سلوكه الافتراضي (إعادة تحميل الصفحة — وهي بالضبط ما يُضيّع التعديل في الذاكرة).
3. استدعاء `POST /builder/session/refresh` وتحديث رمز CSRF.
4. **إعادة المحاولة مرّة واحدة فقط** — بإعادة تشغيل **المسودّة المحليّة** عبر `applyDraft`، لأن الطلب الفاشل لم يصل الخادم فحالته قديمة؛ إعادة المسودّة هي ما يحفظ آخر ما كتبه المستخدم فعلًا.
5. **نفس مفتاح idempotency** — المفتاح مشتقّ من (الدرس، النسخة، الحمولة)، فالإعادة المطابقة تُعيد النتيجة الأولى ولا تُنشئ سجلًا مكرّرًا.
6. إذا فشل التجديد → `markSessionExpired()` تُجمّد **كل** العناصر وتعرض لوحة الاستعادة مع رابط الدخول.
7. بعد الدخول والعودة لنفس الصفحة → تُعرض المسودّة للاستعادة.

## ما يُغطّيه الاختبار (خادميًّا)

1. نطاق المسودّة يختلف باختلاف الكورس **وباختلاف المستخدم** — لا تسرّب بين مستأجر/مستخدم/كورس.
2. استعادة المسودّة تُطبَّق وتُحفظ فعليًا.
3. **المسودّة القديمة لا تُبيح الدهس** — استعادة مسودّة بُنيت على نسخة قديمة تُنتج `conflict` ولا تستبدل عمل الآخر.
4. `builder-node-saved` يُطلق عند الحفظ المؤكَّد **فقط**.
5. لا يُطلق عند الرفض/التعارض — فتبقى المسودّة سليمة على العميل.
6. تجاهل المسودّة يُعيد العنصر إلى `idle`.
7. انتهاء الجلسة يُجمّد كل العناصر ولا يُكتب شيء بعده.

## ما لا يُتحقَّق منه محليًّا (وسببه)

`localStorage` واعتراض 419 وتوقيت الـdebounce سلوكيات متصفّح. تحقّقت مما يمكن بلا اعتماد: تصريف القوالب، ومنطق الخادم كاملًا باختبارات. **الرحلة الكاملة (419 أثناء الكتابة → تجديد → إعادة واحدة → لا تكرار) مكانها Playwright في الزيادة ٤**، وهي مُدرَجة صراحةً هناك.
