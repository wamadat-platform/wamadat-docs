## Critical gaps (🔴) — must close before revenue launch

### [QA-001] No test for `POST /checkout`
- **Module:** Commerce — single biggest revenue path
- **Required scenarios:**
  1. Happy path: items → order → payment intent → redirect
  2. Empty cart rejection
  3. Already-enrolled program rejection
  4. Archived/unpublished program rejection
  5. Invalid coupon rejection

### [QA-002] No test for payment webhook idempotency
- **Endpoints:** `POST /api/v1/webhooks/{gateway}` (mock | tap | tamara)
- **Required:** double-deliver the same `paid` event, assert order finalizes exactly once, enrollment created once, invoice issued once.

### [QA-003] No refund test
- Refund service exists; refund endpoint exists; zero tests.
- **Required:** within-14-day path + outside-window rejection + idempotency.

### [QA-004] Coupon validation untested
- `POST /checkout/coupon/validate` — stacking, expiration, min-cart amount, max-discount cap.

### [QA-005] Gift create/redeem untested
- `POST /me/gifts`, `GET /me/gifts/sent`, `POST /me/gifts/redeem`.
- Edge: expired gift, double-redemption, recipient already enrolled.

## High gaps (🟠)

### [QA-006] Affiliate attribution untested
- `GET /me/affiliate`, `POST /me/affiliate/enroll`, `POST /affiliate/click`, `POST /affiliate/conversion`.

### [QA-007] Consultations endpoint untested
- `GET /consultations/packages`, `POST /consultations/requests` — verify validation + event dispatch.

### [QA-008] Assignment submit untested
- `POST /assignments/{id}/submit` — file URL validation, enrollment re-check on submit.

### [QA-009] Achievement / streak calculations untested
- Side-effect-heavy logic (recompute on lesson completion). Lots of edge cases (timezones, missed days).

### [QA-010] No factories for any model
- Every test inline-creates users + programs + categories. Refactor into `database/factories/{User,Program,Order,...}Factory.php`.

## Medium gaps (🟡)

- [QA-011] No frontend test infrastructure (no `playwright.config.ts`, no Vitest config). Recommend Playwright for the 5 critical user journeys.
- [QA-012] No mutation testing → no signal on test quality.
- [QA-013] No DB-cleanup-between-tests verification — tests rely on Pest's TenantTestCase but a contamination test would be cheap insurance.
- [QA-014] No load testing setup (k6 / Artillery).
- [QA-015] Coverage not measured — `php artisan test --coverage` not in CI.

## Low gaps (🟢)

- [QA-016] Pest snapshot testing not used (would catch unintended JSON-shape changes in API responses).
- [QA-017] No visual regression for design system changes.
- [QA-018] No accessibility tests (axe-core in Playwright).
