# 🎭 UX Audit — Reviewer 4 (UX Researcher, PhD HCI)

**Method:** Walked through 5 primary user journeys end-to-end, file by file, simulating each role's mental model.

---

## Journey 1: Visitor → Buyer (the revenue journey)

**Path:** Home → Programs → Program detail → Add to cart → Cart → Sign up → Checkout → Pay → Confirmation

### Friction points

#### [UX-001] Cart CTA label ambiguous for returning users
- **Path:** `app/[locale]/cart/page.tsx:152-157`
- **Severity:** 🟠 High
- **Issue:** Button reads "سجّل وادفع" assuming guest. Returning user already logged in sees the same text.
- **Suggested:** `isAuthenticated ? 'المتابعة للدفع' : 'سجّل وادفع'` (already conditioned on the field below — apply same logic to button text).

#### [UX-002] No "continue as guest" path
- **Severity:** 🟡 Medium
- **Issue:** Checkout forces account creation before payment.
- **Owner decision needed:** Is guest checkout desired? Reduces friction for low-trust users but loses CRM/repeat hooks.

#### [UX-003] No saved-cart preview on user-menu
- **Severity:** 🟡 Medium
- **Issue:** After login, user must navigate to cart to see what they had. A `Cart (3)` badge on the navbar would help, ideally with hover preview.

## Journey 2: Student → Learning

**Path:** Login → Dashboard → My Programs → Start lesson → Complete → Quiz → Certificate

#### [UX-004] No "continue where I left off" CTA on dashboard
- **Severity:** 🟠 High
- **Issue:** Dashboard greets the user, but the next-most-likely action ("resume last lesson") is buried two clicks away.
- **Suggested:** Hero card at top of `/dashboard` with the most recently-touched lesson.

#### [UX-005] Lesson progress markers visually weak
- **Path:** `components/learn/learn-shell.tsx`
- **Severity:** 🟡 Medium
- **Issue:** Completed lessons indistinguishable from in-progress without close inspection.

#### [UX-006] Quiz cannot be retried explicitly from the failure screen
- **Severity:** 🟠 High (impacts cert completion rate)
- **Issue:** User must navigate back to lesson and click "take quiz" again — not a single "retry" CTA.

## Journey 3: Instructor → Content creator (BROKEN)

#### [UX-007] No instructor onboarding flow exists
- **Severity:** 🔴 Critical (blocker for instructor revenue stream)
- **Issue:** `/become-instructor` page exists with copy but no application form, no admin review queue, no flip from `student` to `instructor` role.
- **Owner decision needed:** Manual onboarding via email only? Self-service application flow?

#### [UX-008] No instructor dashboard
- **Severity:** 🔴 Critical
- **Issue:** Backend has instructor permissions but no UI surface for: create program, manage modules/lessons, see enrollments, grade assignments, see earnings.

## Journey 4: Consultation Request

#### [UX-009] Package selection inside form duplicates package cards above
- **Path:** `app/[locale]/consultations/page.tsx` + `components/consultations/consultation-form.tsx`
- **Severity:** 🟡 Medium
- **Issue:** User picks a package from the cards, scrolls to form, then must re-select inside the form. The anchor `#book?pkg=spark` includes `pkg` but the form doesn't honor it.
- **Suggested:** Parse the hash param and pre-select the matching package in the form.

#### [UX-010] No estimated response time visible at form-submit
- **Severity:** 🟡 Medium
- **Issue:** Success state says "24 hours" but the submit button doesn't preview this — user submits hoping someone will respond.

## Journey 5: Apply as staff / instructor

#### [UX-011] Both `Join as Staff` and `Join as Instructor` route to generic targets
- **Path:** `components/team/join-us-cta.tsx`
- **Severity:** 🟠 High
- **Issue:** Staff CTA → `/contact?topic=join-team` (no special handling). Instructor CTA → `/become-instructor` (static marketing page).
- **Suggested:** Real application forms with topic-specific fields (CV upload for staff; portfolio + sample lesson for instructor).

## Empty states (across journeys)

#### [UX-012] Many empty states say "لا توجد بيانات" without next-action
- **Files:** Various dashboard pages (e.g., `/dashboard/wishlist`, `/dashboard/orders`, `/dashboard/notifications`)
- **Severity:** 🟡 Medium
- **Suggested:** Each empty state should have:
  1. An illustration / icon (already partially done)
  2. A one-sentence "why this is empty"
  3. A clear next action button (e.g., "تصفح البرامج")

## Navigation

#### [UX-013] Mobile menu — no test of long-press / drawer behavior
- **Severity:** 🟢 Low
- **Status:** Manual QA needed.

#### [UX-014] Locale switcher doesn't preserve query params
- **File:** `components/layouts/language-switcher.tsx`
- **Severity:** 🟡 Medium
- **Issue:** Switching ar↔en on `/programs?category=design` drops the filter.
