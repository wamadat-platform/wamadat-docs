## 1. الأدوار الخمسة المعتمدة في Launch V1

تعتمد منصة ومضات نظام التحكم بالوصول المبني على الأدوار (Role-Based Access Control - RBAC). يحدد السورس كود الحالي في `Role.php` خمسة أدوار تشغيلية رئيسية:

```text
┌─────────────────────────────────────────────────────────────────────────┐
│                           System Roles (V1)                             │
├──────────────┬──────────────┬──────────────┬──────────────┬─────────────┤
│   Visitor    │   Student    │  Instructor  │ Attendance   │    Admin    │
│              │              │              │  Operator    │             │
└──────────────┴──────────────┴──────────────┴──────────────┴─────────────┘
```

## 2. نطاق صلاحيات وحدود كل دور (Role Access Boundaries)

### 2.1 الزائر (Visitor)
- **الصلاحيات المتاحة:** تصفح الصفحات التعريفية العامة، البحث في كتالوج البرامج، الاطلاع على ملفات المدربين العامة، إنشاء حساب طالب، وتأكيد البريد.
- **القيود:** يمنع تمامًا من الوصول إلى أي محتوى تعليمي محمي، السلة، أداء الاختبارات، تسليم الواجبات، أو واجهات اللوحات الداخلية.

### 2.2 الطالب (Student)
- **الصلاحيات المتاحة:** تصفح برامجه المسجل بها (`Enrollments`)، قراءة الدروس، أداء الاختبارات، رفع الواجبات، تدوين الملاحظات الشخصية (Lesson Notes)، طرح الأسئلة داخل الدرس (Lesson Q&A)، عرض بطاقة الـ QR الخاصة بالحضور، إصدار وتنزل الشهادات المستحقة، وفتح تذاكر الدعم.
- **القيود والأمان:** عزل بيانات الطلاب تمامًا؛ لا يمكن للطالب الوصول إلى ملاحظات، تذاكر دعم، تسليمات، أو شهادات طالب آخر.

### 2.3 المدرب (Instructor)
- **الصلاحيات المتاحة:** الوصول الحصري للبرامج والدروس والطلاب المسندين إليه رسمياً، تصحيح الواجبات وتحديد الدرجات والتعليقات، والرد على أسئلة الطلاب داخل دروس برامجه.
- **القيود والأمان:** يمنع المدرب من الوصول إلى لوحة الإدارة العامة، ولا يملك أي صلاحيات على البرامج غير المسندة إليه، ولا يملك الوصول لإعدادات المالية أو المدفوعات أو إعدادات الموقع.

### 2.4 موظف الحضور (Attendance Operator)
- **الصلاحيات المتاحة:** تسجيل الدخول المباشر إلى بوابة الحضور الخاصة (`/attendance/sign-in`)، اختيار الجلسة التدريبية المفتوحة المسموح بها، ومسح رموز الـ QR الخاصة بالطلاب عبر كاميرا الجهاز وتأكيد تسجيل الحضور.
- **القيود والأمان الصارمة:** يتم فرض الحماية برمجياً عبر الـ Middleware الخاص (`RestrictAttendanceOperatorApi`). موظف الحضور **محروم تماماً** من الوصول إلى لوحة الطالب، لوحة المدرب، لوحة الإدارة، المحتوى التعليمي، أداة الشراء، أو السجلات المالية.

### 2.5 الإدارة (Admin)
- **الصلاحيات المتاحة:** إدارة كاملة للبرامج، المحتوى، المستخدمين، التسجيلات، مراجعة إيصالات التحويل البنكي، الفواتير، الكوبونات، وإرشادات الموقع من خلال لوحة Filament الإدارية المحمية.

## 3. حماية التنزيلات والمحتوى والمستندات (Media & Document Security)

1. **روابط المحتوى المخصصة (Signed Media URLs):** الموارد والملفات المرفقة بالدروس لا تُكشف بروابط مباشرة دائمًا؛ بل تُولد لها روابط موقعة ومؤقتة (Signed URLs) تضمن عدم التداول الخارجي للملفات المحمية.
2. **إيصالات التحويل البنكي (Bank Transfer Receipts):** تحفظ صور وإيصالات التحويل البنكي في مجلدات تخزين خاصة (Private Storage) ولا يمكن الوصول إليها إلا من قِبل مسؤول الإدارة المخول بمراجعة الطلب.

---

## 4. حماية الأسرار وبيانات الاعتماد (Secret Management Policy)

- **حظر تدوين الأسرار في Git:** يمنع منعًا باتًا تدوين أي كلمات مرور، مفاتيح API حية، أسرار تشفير، أو بيانات دخول تجريبية صريحة داخل وثائق التوثيق أو المستودع (تم حذف `ADMIN_ADD_PROGRAM_GUIDE.md` لهذا السبب).
- **حقن المتغيرات البيئية:** يتم إمداد مفاتيح الخدمة وقواعد البيانات عبر متغيرات البيئة `.env` في بيئات التشغيل الآمنة فقط.
