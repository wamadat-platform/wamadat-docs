# API v1 — CHANGELOG

This file records every API contract change that an external consumer (mobile app, third-party integrator, frontend) needs to know about. Each entry includes:
- Date + commit hash
- Affected endpoints
- Before / After shape (verbatim)
- Migration guidance for clients

When v2 of the API ships, this file freezes — v2 gets its own changelog.

## 2026-05-13 — BREAKING: signed media URLs replace raw `file_url` in `LessonResource.resources[]` (Phase D / CP4-11)

**Commit:** `<filled at commit time>`.

### Summary

Before: `LessonResource::resources[i].file_url` was a raw storage path resolving to a publicly-addressable URL with no auth, no expiry, no scope. Anyone with the link could download forever. After: the field is renamed to `download_url` and emits a signed, scoped, time-limited URL backed by a new `MediaController` that re-verifies enrollment at serve time.

### Affected

- `GET /api/v1/learn/programs/{slug}` — `data.modules[*].lessons[*].resources[*]` no longer carries `file_url`; carries `download_url`.

### Before

```jsonc
{
  "data": {
    "modules": [{
      "lessons": [{
        "resources": [{
          "id": "...",
          "name": "Slides",
          "type": "pdf",
          "file_url": "lesson-resources/abc.pdf",
          "size_bytes": 1024,
          "mime_type": "application/pdf",
          "is_downloadable": true
        }]
      }]
    }]
  }
}
```

### After

```jsonc
{
  "data": {
    "modules": [{
      "lessons": [{
        "resources": [{
          "id": "...",
          "name": "Slides",
          "type": "pdf",
          "download_url": "https://api.wmt.sa/api/v1/media/lesson-resources/<id>?expires=...&user=<userId>&signature=<hex>",
          "size_bytes": 1024,
          "mime_type": "application/pdf",
          "is_downloadable": true
        }]
      }]
    }]
  }
}
```

### Migration guidance

- Mobile/SDK clients reading `resources[i].file_url`: switch to `resources[i].download_url`.
- External-link resources (admin-entered full `https://...` URLs) emit the URL unchanged in `download_url`.
- Downloads MUST include the same `Authorization: Bearer <token>` and `X-Tenant-Slug: <slug>` headers used to obtain the URL. The endpoint validates the signed URL's `user=` query parameter matches the bearer-token user; mismatched, no auth, expired, or tampered URLs all return:
   ```json
   { "error": { "code": "PERMISSION_DENIED", "message": "...", "status": 403, "details": null } }
   ```
- A user who un-enrolled mid-window receives `error.code: NOT_ENROLLED` (403) even with an otherwise-valid signature.
- URL lifetime: 15 minutes (`MediaController::SIGNATURE_TTL_MINUTES`).

Full details + threat model + 7-case live proof matrix in `docs/api/09-signed-media-urls.md`.

### New error-codes catalogue entries

None. All emits route to existing codes (`PERMISSION_DENIED`, `NOT_ENROLLED`, `UNAUTHENTICATED`, `RESOURCE_NOT_FOUND`) — CP4-9 catalogue stays a closed vocabulary.

### Side fix — `InvalidSignatureException` now localized

`ApiErrorRenderer::mapThrowable()` now catches `Illuminate\Routing\Exceptions\InvalidSignatureException` specifically and emits `PERMISSION_DENIED` with `__('errors.permission_denied')` so the response follows `Accept-Language`. Previously the response carried Symfony's hardcoded English `"Invalid signature."` string regardless of locale.

## 2026-05-13 — NON-BREAKING: throttle response code corrected to `RATE_LIMITED` (Phase D / CP4-10)

**Commit:** `<filled at commit time>`.

### Summary

Two-part: (a) corrected a latent namespace bug that caused throttle 429 responses to emit `error.code: "HTTP_ERROR_429"` instead of the documented `"RATE_LIMITED"`. (b) Added throttles to 10 additional sensitive endpoints (account deletion, certificate issuance, review write, 2FA confirm/disable, QR regenerate, password change, checkout, coupon validate, gift create, gift redeem). Total throttled endpoints in v1: 24.

### Affected

Every endpoint that can return a 429. The full catalogue is in `docs/api/07-rate-limits.md`.

### Code mapping — before

```jsonc
HTTP/1.1 429
{ "error": { "code": "HTTP_ERROR_429", "message": "Too Many Attempts.", "status": 429, "details": null } }
```

### Code mapping — after

```jsonc
HTTP/1.1 429
{ "error": { "code": "RATE_LIMITED", "message": "محاولات كثيرة. حاول لاحقاً.", "status": 429, "details": null } }
// Accept-Language: en →  "message": "Too many requests. Please try again later."
```

### Migration guidance

Mobile/SDK clients matching on `HTTP_ERROR_429` (which was undocumented and a contract-drift bug) must switch to `RATE_LIMITED` to match the catalogue. Clients already matching on the canonical `RATE_LIMITED` (per `docs/api/04-error-codes.md`) require no change — this fix brings reality into alignment with the documented contract.

### Why this is NOT breaking

The previous `HTTP_ERROR_429` value was never documented in the v1 contract. The canonical catalogue (CP4-9, committed 2026-05-13) has always specified `RATE_LIMITED` as the only valid 429 code. So this corrects an implementation bug, not a contract change.

## 2026-05-14 — BREAKING (catalog list endpoints): mobile-safe pagination envelope (Phase D / CP4-4)

**Commit:** `<filled at commit time>`.

### Affected
- `GET /api/v1/catalog/programs`
- `GET /api/v1/catalog/instructors`

Tier 2 (`/me/*`) and Tier 3 (`/catalog/categories`, `/me/certificates`) shapes are unchanged.

### Before — Laravel's default `paginate()` envelope

```jsonc
{
  "data": [...],
  "links": {
    "first": "http://api/.../?page=1",
    "last":  "http://api/.../?page=15",
    "prev":  null,
    "next":  "http://api/.../?page=2"
  },
  "meta": {
    "current_page": 1,
    "from": 1,
    "last_page": 15,
    "links": [   // 16-entry nav strip — HTML entities included
      { "url": null, "label": "&laquo; Previous", "active": false },
      { "url": "http://api/.../?page=1", "label": "1", "active": true },
      ...
      { "url": "http://api/.../?page=2", "label": "Next &raquo;", "active": false }
    ],
    "path": "http://api/...",
    "per_page": 2,
    "to": 2,
    "total": 30
  }
}
```

### After — `PaginatedCollection` envelope

```json
{
  "data": [...],
  "meta": {
    "current_page": 1,
    "per_page": 2,
    "total": 30,
    "last_page": 15,
    "has_more": true
  }
}
```

Removed:
- top-level `links` object (server URLs)
- `meta.links[]` (16-entry nav strip with HTML entities)
- `meta.path`, `meta.from`, `meta.to`

Added:
- `meta.has_more` boolean — derived from `current_page < last_page`, the only signal infinite-scroll clients need.

### Migration

- **Mobile clients:** decode using:
  ```swift
  struct Meta: Codable {
    let current_page: Int
    let per_page: Int
    let total: Int
    let last_page: Int
    let has_more: Bool
  }
  ```
- **Frontend (bundled Next.js):** the catalog list components were reading the legacy `meta.links` for the page nav. Update to compute the strip locally from `current_page` + `last_page` (cheap; no server round-trip needed).
- **External integrators:** if you were following `links.next` for "load more", now compute the next URL yourself as `?page=${current_page + 1}` while `has_more === true`.

### Tier classification

Documented in full at `docs/api/06-pagination.md` — three tiers (offset paginated / full collection with domain meta / bounded with no meta), with the per-endpoint table and the smoke check.

## 2026-05-14 — NON-BREAKING: Accept-Language handling (Phase D / CP4-6)

**Commit:** `<filled at commit time>`.

### What landed

- New `SetApiLocale` middleware reads the `Accept-Language` header on every `/api/*` request and sets `App::setLocale('ar'|'en')` for the request lifetime. Supported locales: `ar`, `en`. Anything else falls back to `APP_LOCALE` (Arabic).
- New translation files under `resources/lang/{ar,en}/errors.php` with one entry per `errors.*` key referenced from CP4-9.
- All hardcoded Arabic strings in `ApiErrorRenderer`, `TokenService`, `AuthController`, `SessionsController` replaced with `__('errors.*')` calls that resolve at request time.

### Affected endpoints
- All `/api/v1/*` responses on the error path. Success responses unchanged (no localized content in them today).

### Client contract

```
Request:  Accept-Language: en
Response: { "error": { "code": "UNAUTHENTICATED", "message": "Unauthenticated. Please sign in again.", ... } }

Request:  Accept-Language: ar-SA,en;q=0.5
Response: { "error": { "code": "UNAUTHENTICATED", "message": "غير مصرَّح. سجّل الدخول من جديد.", ... } }
```

The `error.code` machine identifier is the **stable contract** and never localizes — only `error.message`. Mobile clients that ship their own UI strings should ignore `error.message` and key off `error.code`.

### Discovered + tracked

- `R-OPEN-28` — per-field validation messages (inside `error.details`) still come from hardcoded Arabic strings in FormRequest `messages()` arrays. The envelope-level message localizes; the inner per-field messages don't yet. Tracked as a separate light-touch hygiene sweep.

## 2026-05-14 — NON-BREAKING: error codes catalogue + two new code mappings (Phase D / CP4-9)

**Commit:** `<filled at commit time>`.

### What landed
- **`docs/api/04-error-codes.md`** — single source of truth for every `error.code` string emitted by `/api/v1/*`. Grouped into 8 families (AUTH / PERMISSION / VALIDATION / RESOURCE / RATE / TENANT / OPERATION / HTTP / SERVER). Each code carries: HTTP status, retryable-vs-fatal class, UI surface routing, AR + EN message key, emit site. Includes a mobile decision tree and a smoke-check bundle.
- **Two new status→code mappings in `NormalizeApiErrorResponse::deriveCode`:**
    - `400` → `INVALID_REQUEST` (was emitting `HTTP_ERROR_400`).
    - `405` → `METHOD_NOT_ALLOWED` (was emitting `HTTP_ERROR_405`).

### What did NOT change
- No existing emit site changed behaviour. All ApiException::* call sites use the same codes as before.
- The closed vocabulary frozen by the catalogue matches what's already shipping in production today. The doc records reality, it doesn't reshape it.

### Affected clients
- **Mobile / SDK:** ship the catalogue to your client team. The retryable-vs-fatal table is the decision boundary for auto-retry vs. surface-to-user logic.
- **Frontend:** no code change required. Codes the FE already mapped (`INVALID_CREDENTIALS`, `RATE_LIMITED`, etc.) stay identical.
- **External integrators:** read `docs/api/04-error-codes.md` as the authoritative list. Treat unknown codes as `SERVER_ERROR` (fail closed).

### Process change
- **Adding a new code now requires editing `docs/api/04-error-codes.md` first** — the doc is the contract, the code follows. See "Adding a new code" in the catalogue.

### Discovered + tracked
- `R-OPEN-27` — `Model::find($nonUuidString)` returns `SERVER_ERROR` instead of `INVALID_REQUEST`. NewsletterController is the first known site; a quick sweep likely finds ~15 more. Light-touch hygiene; not blocking.

## 2026-05-14 — BREAKING: two-token auth (access + refresh), session management (Phase D / CP4-5)

**Commit:** `<filled at commit time>`.

### Affected
- `POST /api/v1/auth/login` — response body shape change.
- `POST /api/v1/auth/register` — response body shape change.
- `POST /api/v1/auth/logout` — now also revokes the paired refresh token.
- **NEW** `POST /api/v1/auth/refresh` — rotate access + refresh.
- **NEW** `GET /api/v1/me/sessions` — list active devices.
- **NEW** `DELETE /api/v1/me/sessions/{id}` — revoke a specific session.
- **NEW** `DELETE /api/v1/me/sessions` — revoke all sessions except current.

### Behavioural changes
- Access tokens now carry a **60-minute TTL** (Sanctum `expires_at`). After expiry the next request gets `error.code = UNAUTHENTICATED` (401); the client should call `/auth/refresh` and retry once.
- Refresh tokens live in a separate table, **60-day TTL**, sent ONLY in `POST /auth/refresh` body (or `wamadat_refresh` httpOnly cookie path-scoped to `/api/v1/auth`). **NEVER** in `Authorization: Bearer`.
- Refresh is **single-use**: each `/auth/refresh` revokes the input and issues a new pair. The rotation chain is recorded via `replaced_by_id`.
- **Reuse detection:** presenting a refresh token whose `revoked_at` is already set is treated as token theft — every access + refresh token for the user is revoked and the response is `error.code = REFRESH_TOKEN_REUSED`.
- **Device tracking:** login/register accept optional body fields `device_name` (string ≤100), `device_type` (`ios`/`android`/`web`/`api`/`tablet`/`unknown`), `device_id` (client-supplied UUID ≤64). The server records IP + User-Agent automatically.

### Login / register response shape

BEFORE:
```json
{
  "data": {
    "user": { ... },
    "token": "<sanctum-token>",
    "token_type": "Bearer"
  }
}
```

AFTER:
```json
{
  "data": {
    "user": { ... },
    "access_token": "<sanctum-token, 60m TTL>",
    "refresh_token": "<80-char plaintext, 60d TTL>",
    "token_type": "Bearer",
    "expires_in": 3600,
    "refresh_expires_in": 5184000,
    "token": "<DEPRECATED — same value as access_token, for transition only>"
  }
}
```

`data.token` is a transition alias and will be REMOVED after CP4-12 contract tests prove every consumer reads `data.access_token`. Mobile clients should ignore `data.token` from day one.

### New endpoint contracts

```http
POST /api/v1/auth/refresh
Content-Type: application/json
Accept: application/json
X-Tenant-Slug: <tenant>

{
  "refresh_token": "<plaintext from login/register>",
  "device_name": "optional, overrides stored",
  "device_type": "optional",
  "device_id": "optional"
}
```

Response 200:
```json
{
  "data": {
    "access_token": "<new>",
    "refresh_token": "<new>",
    "token_type": "Bearer",
    "expires_in": 3600,
    "refresh_expires_in": 5184000
  }
}
```

Response 401 — possible `error.code` values:
- `REFRESH_TOKEN_MISSING` — body had no `refresh_token` and no cookie.
- `REFRESH_TOKEN_INVALID` — unknown plaintext (or race-loss to a concurrent refresh of the SAME token).
- `REFRESH_TOKEN_EXPIRED` — past `expires_at`.
- `REFRESH_TOKEN_REUSED` — caller knew an old, already-rotated refresh. **All user tokens revoked** before this is returned.
- `ACCOUNT_INACTIVE` — user `is_active=false` or `is_blocked=true`.

```http
GET /api/v1/me/sessions
Authorization: Bearer <access>
Accept: application/json
X-Tenant-Slug: <tenant>
```

Response 200:
```json
{
  "data": [
    {
      "id": 110,
      "is_current": true,
      "device_name": "iPhone 15 Pro",
      "device_type": "ios",
      "device_id": "AAAA-BBBB",
      "ip": "31.166.x.x",
      "user_agent": "WamadatApp/1.0 (iPhone; iOS 18.0)",
      "last_used_at": "2026-05-14T12:30:01Z",
      "created_at": "2026-05-13T09:00:00Z",
      "expires_at": "2026-05-13T10:00:00Z"
    }
  ],
  "meta": { "total": 1, "current_session_id": 110 }
}
```

```http
DELETE /api/v1/me/sessions/{id}
Authorization: Bearer <access>
```
- `204` on success.
- `404 SESSION_NOT_FOUND` if the id doesn't belong to the current user.
- `422 CANNOT_REVOKE_CURRENT_SESSION` if `id` equals the caller's own session — use `/auth/logout` instead.

```http
DELETE /api/v1/me/sessions
Authorization: Bearer <access>
```
Revokes every session EXCEPT the current one.
Response 200: `{ "data": { "access_revoked": N, "refresh_revoked": N } }`.

### Cookies (web only)

Both tokens are also returned as httpOnly cookies for the bundled Next.js frontend:
- `wamadat_session` — access token, path `/`, expire `access_expires_in`.
- `wamadat_refresh` — refresh token, **path `/api/v1/auth`** (limits exposure to auth endpoints only), expire `refresh_expires_in`.

Both cookies are `httpOnly` + `secure` (in HTTPS) + `SameSite=Lax`. JavaScript cannot read them. `POST /auth/refresh` reads `refresh_token` from body first, falls back to the cookie — so the same backend code path serves both web and mobile.

### Migration guidance

**Mobile (Swift / Kotlin):**
```swift
struct LoginResponse: Codable {
  struct Data: Codable {
    let user: User
    let access_token: String
    let refresh_token: String
    let token_type: String
    let expires_in: Int
    let refresh_expires_in: Int
  }
  let data: Data
}

// Persist access + refresh in OS keychain (NOT UserDefaults).
// Send Authorization: Bearer <access>.
// On 401 with error.code = UNAUTHENTICATED, call /auth/refresh once,
// then retry the original request. If refresh also fails, route to login.
```

**Frontend (bundled Next.js — already updated in this commit):**
`lib/api/client.ts` now installs an `afterResponse` ky hook that:
1. On a 401 that isn't from `/auth/refresh|login|logout`, calls `attemptRefresh()` (single-flight).
2. If the refresh succeeds, retries the original request once (with header `x-wamadat-retry: 1` to prevent loops).
3. Otherwise lets the 401 propagate so the app can route to `/sign-in`.

**External integrators (none today):** read `data.access_token` for the auth header. Store `data.refresh_token` securely. Implement the same 401-retry-once-then-give-up pattern.

### DB impact

Migration `2026_05_14_080000_create_refresh_tokens_and_device_metadata` adds:
- 5 columns on `personal_access_tokens`: `device_name`, `device_type`, `device_id`, `last_ip`, `last_user_agent` + `pat_user_device_idx` index.
- New `refresh_tokens` table (UUID-keyed user_id, sha256 token_hash, expires_at, revoked_at, replaced_by_id, device fields, indexes).

Existing 87 `web-session` tokens stay valid until they're naturally pruned or the user logs in again (new logins issue the new shape).

### Security impact — POSITIVE
- Access tokens now have a 60-minute blast radius instead of infinity.
- Refresh-token reuse is a hard alarm that revokes EVERY user session.
- Refresh tokens cannot be used on protected endpoints (different table, different transport).
- Sessions endpoint lets users self-revoke a lost device without a support ticket.
- Logout now revokes the FULL pair, not just the access token — closes the previous "logout but refresh still alive" gap.

### Remaining risks
- Password-change does NOT yet auto-revoke all sessions (planned follow-up).
- Frontend `parseApiError` still reads legacy shapes — same transition rule as CP4-2.
- Old `web-session` tokens issued before this commit have `expires_at=NULL` (infinite lifetime). Not auto-pruned. Operator may run a one-off `DELETE FROM personal_access_tokens WHERE expires_at IS NULL` after a maintenance window.
- The `data.token` alias on login/register exists for transition only. Schedule its removal in CP4-12 contract-test commit.

## 2026-05-13 — BREAKING: canonical error response shape (Phase D / CP4-2)

**Commits:** `ae2dd5e` (rebuild) + closeout (`/health` bypass fix).

### Affected
All `/api/v1/*` endpoints **on the error path** (any 4xx / 5xx response). Success responses (2xx) are unchanged.

**Exclusions** (deliberately not normalized):
- `POST /api/v1/webhooks/{gateway}` — gateways have their own response contract.
- `POST /api/v1/webhooks/resend` — same.
- `GET /api/v1/health` — deliberately ships 503 with structured `checks.*` for monitoring systems.

### Before — six observed shapes
```jsonc
// Laravel FormRequest default
{ "message": "...", "errors": { "field": ["..."] } }

// AuthController INVALID_CREDENTIALS
{ "errors": [ { "code": "INVALID_CREDENTIALS", "title": "...", "detail": "..." } ] }

// Auth middleware unauthenticated
{ "message": "غير مصرح..." }

// Tenant-required handler
{ "message": "...", "code": "TENANT_REQUIRED", "hint": "..." }

// Bare 404 from controllers
{ "message": "البرنامج غير موجود." }

// Throttled
{ "errors": [ { "code": "...", "title": "...", "detail": "..." } ] }
```

### After — one canonical shape
```json
{
  "error": {
    "code": "STABLE_SCREAMING_SNAKE_CASE",
    "message": "Localized human-readable",
    "status": 422,
    "details": null | { "field": ["..."] } | [ ... ]
  }
}
```

### Closed code vocabulary in this release
| Code | HTTP | Emitted when |
|---|---|---|
| `INVALID_CREDENTIALS` | 401 | Login wrong email/password |
| `UNAUTHENTICATED` | 401 | Missing/expired token, must re-login |
| `PERMISSION_DENIED` | 403 | Authorization or AccessDenied |
| `RESOURCE_NOT_FOUND` | 404 | Route not found, model not found |
| `CONFLICT` | 409 | Generic 409 abort |
| `METHOD_NOT_ALLOWED` | 405 | HTTP verb mismatch |
| `VALIDATION_FAILED` | 422 | FormRequest validation failed — `details` carries `{field: [msg, …]}` |
| `OPERATION_FAILED` | 422 | Generic 422 from controller-level guard (e.g. coupon invalid) |
| `TENANT_REQUIRED` | 422 | `/api/*` without an X-Tenant-Slug header / subdomain |
| `RATE_LIMITED` | 429 | Throttle middleware tripped |
| `SERVER_ERROR` | 500 | Anything else — message hidden in production |
| `HTTP_ERROR_{N}` | N | Fallback for any unmapped 4xx/5xx |

Further `code` values will land in CP4-9 (catalogue) — `LOCKED`, `OTP_INVALID`, `ACCOUNT_INACTIVE`, etc. — at which point this table moves to `04-error-codes.md`.

### Migration guidance

**For a mobile client (Swift / Kotlin), decode every error like this:**

```swift
struct ApiError: Codable {
  let code: String
  let message: String
  let status: Int
  let details: AnyCodable?   // nil OR { String: [String] } OR [Any]
}

struct ApiErrorEnvelope: Codable {
  let error: ApiError
}
```

```kotlin
@Serializable
data class ApiError(
  val code: String,
  val message: String,
  val status: Int,
  val details: JsonElement? = null,
)
@Serializable data class ApiErrorEnvelope(val error: ApiError)
```

**For the frontend** (`lib/api/client.ts`): the bundled `parseApiError` reads the canonical shape first AND retains legacy-shape fallbacks for the transition window. No client code change needed today; the legacy fallbacks get deleted in a follow-up commit after CP4-12 contract tests prove the canonical shape is the only emission left.

**For any external integrator** (none today, but on the record): switch to reading `body.error.code` / `body.error.message`. Any reader of the prior shapes still works during the transition because the middleware emits `error.*` AND removes the legacy keys — so old readers will fail-soft and surface a generic "unknown error" rather than crash. Confirm your client treats unknown shapes safely.

### Webhook ergonomics

Webhook receivers continue to emit `{"ok": true}` / `{"ok": false, "reason": "..."}` as they did pre-Phase-D. The renderer + middleware both bypass `/api/v1/webhooks/*` deliberately.
